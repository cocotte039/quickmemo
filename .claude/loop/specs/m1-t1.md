# T1.1: processVoiceResult の二重呼び出し防止 + 状態クリーンアップ統一

## 目的

`processVoiceResult()` が複数のパス（stopVoiceMemo からの直接呼び出し + onend コールバック）から呼ばれた際に、二重実行を防止する。後続の全修正の前提となる防御的ガード。

## 変更対象

| ファイル | 変更概要 |
|---|---|
| `app.js` | voiceState に `processing` フラグ追加、resetVoiceState にリセット追加、processVoiceResult にガード追加 |

## 詳細仕様

### 1. voiceState に `processing` フラグを追加

```javascript
// app.js:23-32 の voiceState オブジェクト
const voiceState = {
  recording: false,
  finalSegments: [],
  engine: null,
  cancelled: false,
  appendMode: false,
  appendTargetId: null,
  appendCursorPos: null,
  abortController: null,
  processing: false,  // ← 追加
};
```

### 2. resetVoiceState に `processing` のリセットを追加

```javascript
// app.js:34-43 の resetVoiceState 関数
function resetVoiceState() {
  voiceState.recording = false;
  voiceState.finalSegments = [];
  voiceState.engine = null;
  voiceState.cancelled = false;
  voiceState.appendMode = false;
  voiceState.appendTargetId = null;
  voiceState.appendCursorPos = null;
  voiceState.abortController = null;
  voiceState.processing = false;  // ← 追加
}
```

### 3. processVoiceResult の先頭にガードを追加

```javascript
// app.js:1584 の processVoiceResult 関数の先頭
async function processVoiceResult() {
  if (voiceState.processing) return;  // ← 追加: 二重呼び出し防止
  voiceState.processing = true;       // ← 追加
  // ... 既存コード ...
}
```

### 4. processVoiceResult の全完了パスで resetVoiceState を呼ぶ

現在の完了パス:
- キャンセル時 (app.js:1585-1589): 既に `resetVoiceState()` を呼んでいる ✓
- 空テキスト時 (app.js:1590-1597): `voiceState.engine = null` のみ → `resetVoiceState()` に統一する
- 追記モード完了時 (app.js:1630): 既に `resetVoiceState()` を呼んでいる ✓
- 新規メモモード完了時 (app.js:1668): `voiceState.engine = null` のみ → `resetVoiceState()` に統一する

## 受入条件

- [ ] `processVoiceResult()` を2回連続で呼び出しても、2回目は何もしないこと
- [ ] 全完了パス（キャンセル・空テキスト・追記・新規メモ）で `voiceState.processing` が false にリセットされること
- [ ] 正常な録音→停止→結果処理のフローが変わらないこと

## テスト方針

- Chrome DevTools Console で手動テスト
- `processVoiceResult()` 内の先頭に `console.log('processVoiceResult called, processing:', voiceState.processing)` を追加して確認（テスト後に削除）
- シナリオ: 録音→停止→結果がNULLにならないこと（ガードが誤って正常な呼び出しをブロックしていないか）

## 依存関係

- 前提: なし（他の全修正の前提となるタスク）
- ブロック: T1.2, T1.3, T1.4, T1.5 はこのタスクの完了を前提とする

## 注意事項

- `processing` フラグは `processVoiceResult` の末尾ではなく `resetVoiceState()` 内でリセットする設計。これにより、どのパスで完了してもフラグが確実にリセットされる。
- `resetVoiceState()` を呼ぶ前に `voiceOverlay.hidden = true` などの UI 操作が必要な箇所では、UI操作を先に行ってから `resetVoiceState()` を呼ぶ順序を維持する。

# T1.3: dedup ロジックの強化

## 目的

finalSegments への重複テキスト追加を防止する dedup ロジックを強化する。現在は直前セグメントとの完全一致のみチェックしているが、auto-restart のタイミングによっては離れた位置で同一テキストが出現する可能性がある。

## 変更対象

| ファイル | 変更概要 |
|---|---|
| `app.js` | startVoiceMemo / startVoiceAppend 内の onResult コールバックの dedup 条件を強化 |

## 詳細仕様

### 1. dedup ロジックの強化

現在のコード（app.js:1456-1461）:
```javascript
if (isFinal) {
  const segments = voiceState.finalSegments;
  if (segments.length === 0 || segments[segments.length - 1] !== text) {
    voiceState.finalSegments.push(text);
  }
}
```

変更後:
```javascript
if (isFinal) {
  const segments = voiceState.finalSegments;
  // 直近3セグメントとの完全一致をチェック
  const recentSegments = segments.slice(-3);
  const isDuplicate = recentSegments.includes(text);
  // 結合テキストの末尾との重複もチェック（auto-restart で同じ文が分割・再送される場合）
  const joinedText = segments.join('');
  const isSuffixDuplicate = joinedText.length > 0 && joinedText.endsWith(text);
  if (!isDuplicate && !isSuffixDuplicate) {
    voiceState.finalSegments.push(text);
  }
}
```

同様の変更を `startVoiceAppend` 内の `engine.onResult` にも適用する。

### 2. 共通化の検討

startVoiceMemo と startVoiceAppend で同じ dedup ロジックが重複する。T2.4（コールバック共通化）で解消されるが、Phase 1 では両方に同じコードを配置する。

## 受入条件

- [ ] 直前だけでなく直近3セグメント内の重複が除去されること
- [ ] 結合テキストの末尾と一致するテキストが除去されること
- [ ] 意図的に同じフレーズを繰り返した場合（4回以上離れた位置）は正常に記録されること

## テスト方針

- 手動テスト: 同じフレーズを連続で3回発話し、1回のみ記録されることを確認
- 手動テスト: 間に別のフレーズを挟んで同じフレーズを発話した場合は、両方記録されることを確認
- Console で `voiceState.finalSegments` を確認

## 依存関係

- 前提: T1.1（processVoiceResult の二重呼び出し防止）
- 並行可能: T1.2（インスタンス管理改善）

## 注意事項

- dedup が厳しすぎると意図的な繰り返しが消える。直近3セグメント + 末尾完全一致のみに制限することで、「4回以上離れた同一フレーズ」は正常に記録される。
- `isSuffixDuplicate` は `joinedText.endsWith(text)` で判定する。`text` が空文字列の場合は `endsWith('')` が true を返すが、Web Speech API は通常空文字列を final result として返さない。念のため `text.trim()` が空の場合はスキップする処理を追加してもよい。

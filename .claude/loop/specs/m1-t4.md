# T1.4: stopVoiceMemo の即時UI反映 + onend デッドロック防止

## 目的

停止ボタンタップ時の体感遅延をゼロにする。現在は `engine.stop()` → ブラウザの非同期停止 → `onend` 発火 → `processVoiceResult()` という流れで遅延が発生している。

## 変更対象

| ファイル | 変更概要 |
|---|---|
| `app.js` | `stopVoiceMemo()` で即時UI更新 + 直接 `processVoiceResult()` 呼び出し |
| `style.css` | pulse アニメーション停止用クラス（オプション） |

## 詳細仕様

### 1. stopVoiceMemo の改修

現在のコード（app.js:1562-1567）:
```javascript
function stopVoiceMemo() {
  voiceState.recording = false;
  if (voiceState.engine) {
    voiceState.engine.stop();
  }
}
```

変更後:
```javascript
function stopVoiceMemo() {
  voiceState.recording = false;

  // 即時UI更新: ボタン非表示
  voiceStopBtn.hidden = true;
  voiceCancelBtn.hidden = true;

  // モードに応じたUI切り替え
  if (voiceState.appendMode) {
    voiceStatusLabel.textContent = '保存中...';
  } else {
    voiceStatus.hidden = true;
    voiceProcessing.hidden = false;  // スピナー即表示
  }

  // エンジン停止
  if (voiceState.engine) {
    voiceState.engine.stop();
  }

  // 直接 processVoiceResult を呼び出し（onend を待たない）
  processVoiceResult();
}
```

### 2. onend コールバックの二重呼び出し対策

onend 内の `processVoiceResult()` 呼び出しは維持するが、T1.1 で追加した `voiceState.processing` ガードにより二重呼び出しは自動的に防止される。変更不要。

```javascript
// app.js:1471-1475 (既存、変更不要)
engine.onEnd = () => {
  if (!voiceState.recording) {
    processVoiceResult();  // processing ガードで二重呼び出し防止
  }
};
```

### 3. processVoiceResult 内の UI 操作の調整

`processVoiceResult()` 内で行っている UI 操作（ボタン非表示、スピナー表示）は、stopVoiceMemo で既に行われている場合がある。冪等な操作（`hidden = true` の再設定）なので問題ないが、不要な DOM 操作を避けるため、processing ガードの後に UI 状態を確認する方式も検討。

→ 結論: `hidden = true` の再設定は非常に軽量なので、冪等性を利用してそのまま残す。

## 受入条件

- [ ] 停止ボタンタップ直後に録音 UI（パルス、ボタン）が消えること
- [ ] 新規メモモード: 停止直後にスピナー（Summarizing...）が表示されること
- [ ] 追記モード: 停止直後に「保存中...」ラベルが表示されること
- [ ] Gemini API 呼び出し中にオーバーレイが正しく表示され続けること
- [ ] 正常な結果処理（メモ保存・エディタ表示）が変わらないこと

## テスト方針

- 手動テスト: 録音→停止ボタンタップ→UI が即座に切り替わることを目視確認
- 手動テスト: 新規メモモードで停止→Gemini 要約→メモ保存→エディタ表示の全フロー確認
- 手動テスト: 追記モードで停止→テキスト追記→エディタ更新の全フロー確認
- 手動テスト: 短い録音（2秒）→停止→結果が正しいこと（auto-restart 前のケース）

## 依存関係

- 前提: T1.1（processVoiceResult の二重呼び出し防止）— processing ガードが必須
- 推奨: T1.2（インスタンス管理改善）が先に入っていると、stop 後の遅延 final result 処理がクリーン

## 注意事項

- `engine.stop()` は非同期。stop() 呼び出し後も数百ミリ秒間は `onresult` が発火する可能性がある。T1.2 のガード（`!voiceState.recording && isFinal` → return）でこれを防ぐ。
- `processVoiceResult()` は async 関数。stopVoiceMemo から呼び出す際に await は不要（UI は即時に更新され、Gemini API 呼び出しは非同期で進行する）。

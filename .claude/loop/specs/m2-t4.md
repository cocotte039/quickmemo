# T2.4: コールバック共通化リファクタリング

## 目的

`startVoiceMemo()` と `startVoiceAppend()` で重複している engine コールバック設定コードを共通関数に抽出し、保守性を向上させる。

## 変更対象

| ファイル | 変更概要 |
|---|---|
| `app.js` | `setupEngineCallbacks(engine)` 関数を新設、startVoiceMemo / startVoiceAppend から呼び出し |

## 詳細仕様

### 1. 共通関数の抽出

```javascript
function setupEngineCallbacks(engine) {
  engine.onResult = (text, isFinal) => {
    if (voiceState.cancelled) return;
    if (!voiceState.recording && isFinal) return;
    if (isFinal) {
      const segments = voiceState.finalSegments;
      const recentSegments = segments.slice(-3);
      const isDuplicate = recentSegments.includes(text);
      const joinedText = segments.join('');
      const isSuffixDuplicate = joinedText.length > 0 && joinedText.endsWith(text);
      if (!isDuplicate && !isSuffixDuplicate) {
        voiceState.finalSegments.push(text);
      }
    }
    renderTranscript(text, isFinal);
  };

  engine.onError = (error) => {
    showToast('Voice error: ' + error, 'danger', 4000);
    stopVoiceMemo();
  };

  engine.onEnd = () => {
    if (!voiceState.recording) {
      processVoiceResult();
    }
  };
}
```

### 2. 呼び出し側の変更

`startVoiceMemo()`:
```javascript
// 現在の engine.onResult = ..., engine.onError = ..., engine.onEnd = ... を削除
// 代わりに:
setupEngineCallbacks(engine);
engine.start();
```

`startVoiceAppend()`:
```javascript
// 現在の engine.onResult = ..., engine.onError = ..., engine.onEnd = ... を削除
// 代わりに:
setupEngineCallbacks(engine);
engine.start();
```

### 3. 配置場所

`setupEngineCallbacks` は `startVoiceMemo` の直前（Voice Memo セクション内）に配置する。

## 受入条件

- [ ] 動作が変更前と完全に同一であること
- [ ] startVoiceMemo と startVoiceAppend のコールバックコードが共通化されていること
- [ ] 新規メモモード・追記モードの両方が正常に動作すること

## テスト方針

- 手動テスト: 新規メモの録音→停止→要約→保存の全フロー
- 手動テスト: 追記の録音→停止→テキスト追記の全フロー
- 手動テスト: 録音中にキャンセル→次の録音が正常に動作すること

## 依存関係

- 前提: M1（Phase 1）の全タスクが完了していること（特に T1.3 の dedup ロジック）
- 推奨: T2.1, T2.2, T2.3 の後に実施（リファクタリングは他の変更が安定してから）

## 注意事項

- リファクタリングのみで動作変更はないが、Phase 1 の修正と同時に行うとコンフリクトリスクがあるため、Phase 1 完了後に実施する。
- 将来的に新規メモモードと追記モードでコールバックの振る舞いを分けたくなった場合は、`setupEngineCallbacks` にオプション引数を追加する形で拡張できる。

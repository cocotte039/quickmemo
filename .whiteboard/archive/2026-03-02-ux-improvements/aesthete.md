# 審美家分析: QuickMemo UX改善

## サマリー（3行以内）

デザイントークンとダークテーマの骨格は秀逸だが、「アーカイブの一括操作不在」「スワイプ操作の発見性ゼロ」「状態変化のフィードバック不足」が日常利用の心地よさを大きく損なっている。
スペーシング・タイポグラフィの一貫性は高い水準にあるものの、空状態の演出やマイクロインタラクションに "呼吸感" が足りず、触っていて楽しいアプリにはあと一歩届いていない。

---

## 改善提案一覧（優先度順）

### 1. アーカイブ一括削除（"Delete All" アクション）
- **問題**: アーカイブタブにメモが蓄積しても、1件ずつスワイプで削除するしかない。ユーザーが「溜まったアーカイブを掃除したい」と思った瞬間、20件あれば20回スワイプが必要。これは明確なストレスポイントであり、ユーザーから報告済みの課題でもある。
- **改善案**: Archiveタブのヘッダーまたはタブ周辺に「Delete All」ボタンを設置。タップ後に確認ダイアログ（"Delete all N archived memos?"）を表示し、承認で一括永久削除。Undoは5秒間のToastで提供する。
- **期待される効果**: アーカイブ掃除が1タップ+1確認に短縮。心理的に「溜めても大丈夫」と安心できる。
- **優先度**: **High**

### 2. スワイプ操作のオンボーディング / 発見性の向上
- **問題**: アーカイブ・削除の唯一の導線がスワイプだが、それを示す視覚的手がかり（affordance）が一切ない。初めてアプリを開いたユーザーは「メモをどうやって消すのか」がわからない。空状態のテキスト "No memos yet. Tap + to create one." は作成しか教えない。
- **改善案**: (A) 初回起動時にメモアイテムの右端にうっすら矢印アイコン（左スワイプヒント）を表示し、2秒後にフェードアウト。(B) 空状態テキストに "Swipe left to archive" の一文を追加。(C) 長押しでコンテキストメニュー（Archive / Delete / Pin / Color）も検討。
- **期待される効果**: 操作の学習コストがゼロに近づく。「説明なしで使える」水準に到達。
- **優先度**: **High**

### 3. 空状態（Empty State）の情感ある演出
- **問題**: 空状態が灰色テキスト1行だけ。背景色と溶け合って存在感が薄く、「ここから始めよう」という前向きな気持ちを誘発しない。ユーザーが初めてアプリを開いた瞬間、感情的に "冷たい" 印象を受ける。
- **改善案**: アプリアイコンのモチーフ（メモ用紙）を使ったシンプルなSVGイラストを配置。テキストは日本語/英語両対応で「メモはまだありません / + をタップして作成」のように2行に分け、フォントサイズにメリハリをつける。アーカイブ空状態は「全て片付きました」のような達成感のある文言に。
- **期待される効果**: 初回起動の第一印象が温かくなり、アプリへの親しみが生まれる。
- **優先度**: **Medium**

### 4. 画面遷移時のフォーカス管理とキーボード体験の改善
- **問題**: `openEditor` では `setTimeout(() => editorTextarea.focus(), 260)` でフォーカスを当てているが、遷移アニメーション（250ms）とのタイミングが微妙で、端末によってはキーボードが一瞬遅れて出現し「カクッ」とした感触になる。また、エディタを開いた直後にタイトル欄ではなく本文にフォーカスが飛ぶ設計意図は理解できるが、新規メモの場合はタイトルに先にフォーカスする方が自然。
- **改善案**: `transitionend` イベントを使って、アニメーション完了後に確実にフォーカスする。新規メモ（body が空）のときは `editorTitle` にフォーカス。既存メモは従来通り `editorTextarea` の末尾にフォーカス。
- **期待される効果**: 遷移のリズムが途切れなくなり、「開いて即書き始められる」感覚が向上。
- **優先度**: **Medium**

### 5. コピーボタンのフィードバック強化
- **問題**: リスト上のコピーボタンは `memo-item__copy--copied` クラスで色が緑に変わるだけ。変化が小さく、暗いテーマ上では「コピーできた？」と不安になる。エディタ側のコピーボタンには視覚フィードバックがない（Toastのみ）。
- **改善案**: コピーボタンにチェックマークアイコンへの切り替えアニメーション（SVGモーフまたはアイコン差し替え + scale バウンス）を追加。0.3秒のスケールアニメーション（1.0 -> 1.2 -> 1.0）で「押した」実感を与える。エディタ側も同様にアイコン変化を入れる。
- **期待される効果**: 「コピーできた」という確信が視覚的に即座に得られ、安心感が増す。
- **優先度**: **Medium**

### 6. Markdownツールバーのタッチターゲット改善と視認性向上
- **問題**: 各キーは `flex: 1` で幅が均等分割されるが、8個のキーを画面幅で割ると、iPhone SE (375px) で約47px/キー。高さ 2.75rem (44px) は最低限のタッチターゲットを満たすが、横幅が狭い端末では誤タップが起きやすい。また `Tab` `Home` `End` はMarkdown記法ではなく「カーソル操作」であり、性質の異なるものが同列に並んでいるのは認知的に混乱する。
- **改善案**: ツールバーを横スクロール可能にし、各キーの最小幅を 48px に保証。Markdown記法キー（# - > ` *）とカーソル操作キー（Tab Home End）の間にセパレーターを入れ、視覚的にグループ分けする。
- **期待される効果**: 誤タップ減少。機能の性質が一目で区別でき、認知負荷が下がる。
- **優先度**: **Medium**

### 7. スワイプ操作の物理的フィードバック強化
- **問題**: スワイプ中にバイブレーション（10ms）は入るが、視覚的には背景色のフェードインだけ。スワイプが閾値を超えた瞬間の「ここで離せば実行される」感覚が弱い。
- **改善案**: 閾値到達時にアイコンのスケールをバウンスさせる（1.0 -> 1.3 -> 1.0, 150ms）。背景色も閾値前後で彩度・明度を切り替え、「ロックイン」感を演出する。スワイプ中のテキスト "Archive" / "Delete" にアイコン（箱 / ゴミ箱のSVG）を追加して意味を補強する。
- **期待される効果**: スワイプ操作に確信と気持ちよさが生まれ、誤操作も減る。
- **優先度**: **Medium**

### 8. Toast と FAB の重なり問題
- **問題**: Toastは `bottom: calc(env(safe-area-inset-bottom) + 1rem)` に表示される。FABは `bottom: calc(env(safe-area-inset-bottom) + 1.5rem)`。アーカイブ操作後のUndoトーストがFABの直下に表示され、「Undo」ボタンをタップしようとしてFABに触れるリスクがある。Voice FABは更に上にあるため、Toastと重なる可能性は低いが、FABとの距離感は詰まっている。
- **改善案**: Toastの bottom を FAB の上に確実に配置する（`bottom: calc(env(safe-area-inset-bottom) + 1.5rem + 3.5rem + 1.5rem)` 程度）。または、Toastをトップから表示する形式に変更する。
- **期待される効果**: Undo操作の確実性が上がり、「取り消したかったのに新規メモが開いた」事故がなくなる。
- **優先度**: **Medium**

### 9. ピン留めの視覚的重みの不足
- **問題**: ピン留めメモは 14px のピンアイコンが title-row の左に付くだけ。ピン留めグループと非ピン留めグループの間のディバイダーも `height: 1px` の細線で、ピン留めの「特別感」が希薄。ユーザーが「あのピン留めしたメモどこだっけ」と探すとき、目立ちにくい。
- **改善案**: ピン留めメモの背景色を `var(--bg-surface)` に変更してグループ全体を視覚的に浮かせる。ディバイダーにラベル（"Pinned" / "Others"）を添える。ピンアイコンを `var(--accent)` 色に変更。
- **期待される効果**: ピン留めの「特別な位置づけ」が視覚的に明確になり、探す時間が短縮。
- **優先度**: **Low**

### 10. カラータグの活用度向上
- **問題**: カラータグはメモアイテムの左ボーダー 3px でのみ表示。一覧で見たとき、色がボーダーにしか現れないため、メモが多くなると色での視覚的フィルタリングが効きにくい。また、カラーでのフィルタリング機能が存在しない。
- **改善案**: (A) メモアイテムの背景に色のごく淡いティント（opacity: 0.05程度）を加え、色の面積を増やす。(B) 将来的にリストヘッダーに色フィルターチップを追加。
- **期待される効果**: 色が「見分けるための道具」として実用的になる。
- **優先度**: **Low**

### 11. セーブインジケーターの位置と表現
- **問題**: 保存成功のチェックマーク (save-indicator) はヘッダー内の pin ボタンの左に表示される。ヘッダーにはボタンが密集しており（戻る / スペーサー / セーブ / ピン / カラー / コピー）、ユーザーの視線がエディタ本文にあるとき、ヘッダー上部の小さなチェックマークの出現に気づかない可能性がある。
- **改善案**: 保存フィードバックをエディタ本文エリアの右下にフローティングで表示するか、ヘッダーのタイトル位置に "Saved" テキストを一瞬オーバーレイする。サイズを少し大きく（20px）し、フェードイン/アウトに加えて微小なスケールアニメーション（0.8 -> 1.0）を加える。
- **期待される効果**: 「保存された」安心感が作業の流れを中断せずに伝わる。
- **優先度**: **Low**

### 12. 日付フォーマットの相対表示
- **問題**: 日付が `2026-02-27 14:30` のISO風フォーマットで固定表示。「5分前」「昨日」のような相対表示がないため、メモの鮮度が一目でわからない。
- **改善案**: 24時間以内は「N分前」「N時間前」、7日以内は「昨日」「3日前」、それ以降はフォーマット表示。
- **期待される効果**: メモリストのスキャン速度が向上し、「どれが最近のメモか」が直感的にわかる。
- **優先度**: **Low**

## 詳細分析

### 1. 視覚的一貫性

**良い点**:
- CSS変数（デザイントークン）の設計が非常に整理されている。色（背景4段階、テキスト3段階、セマンティック3色）、スペーシング（space-1 ~ space-8）、フォントサイズ（text-xs ~ text-xl）が体系的に定義されており、一貫性の基盤として優秀。GitHub Dark テーマを思わせるカラーパレット (`#0d1117`, `#161b22`, `#21262d`) は、コード/テキスト入力ツールとしてのアイデンティティを明確にしている。
- `--font-mono` と `--font-ui` の使い分けが意図的で、エディタ・プレビューはモノスペース、UI要素はシステムフォントという棲み分けが守られている。
- BEM記法に近い命名規則（`.memo-item__title`, `.voice-overlay__content`）が概ね一貫している。

**課題**:
- `border-radius` 値がトークン化されていない。`0.375rem`（6px）、`0.5rem`（8px）、`0.75rem`（12px）、`50%` が混在している。ボタン類は 0.375rem、ドロップダウン/Toast は 0.5rem/0.75rem と方向性はあるが、明文化されたトークンがないため、今後の拡張で崩れるリスクがある。
- `box-shadow` が `0 4px 12px rgba(0, 0, 0, 0.4)` で3箇所（FAB, color-picker, dropdown-menu, toast）に同一値でハードコードされている。`--shadow-elevated` のようなトークンに統一すべき。
- メモカラーの値（`--memo-color-blue: #3b82a0` 等）は落ち着いたトーンで統一されているが、ダークテーマ上での視認性（特にamberとbg-hover）がやや近い色域で、区別しにくい場面がある。

### 2. ビジュアルヒエラルキー

**良い点**:
- メモアイテムの情報構造（タイトル > プレビュー > 日付）がフォントサイズ・ウェイト・色の3要素でクリアに段階付けされている。`text-lg/600/text-primary` -> `text-sm/normal/text-secondary` -> `text-xs/normal/text-tertiary` の3段構成は教科書的で美しい。
- Active/Archive タブの切り替えは `--accent` 色のボーダーで明確。
- FABの `box-shadow` と色（`--accent-subtle` の青）が画面上で最も注意を引く要素として適切に設計されている。

**課題**:
- エディタヘッダーのボタンが5個（戻る、ピン、カラー、コピー + セーブインジケーター）並んでおり、視覚的な重要度が均一。ピンとカラーは「メタデータ設定」、コピーは「アクション」、戻るは「ナビゲーション」と性質が異なるが、全て同じ `2.75rem x 2.75rem` のグレーアイコンで並んでいるため、ヒエラルキーが平坦。
- ドロップダウンメニュー内の「Export JSON」と「Settings」も同じスタイル。利用頻度が異なるにも関わらず視覚的重みが同じ。

### 3. マイクロインタラクション

**良い点**:
- 画面遷移のアニメーション（`translateX(100%) -> translateX(0)`, 250ms, cubic-bezier）は滑らかで適切な速度。リストビューが `translateX(-30%)` + `opacity: 0.5` で "奥に引く" 演出も深度感を出している。
- スワイプ操作のバイブレーション（閾値到達時に10ms）は、ハプティクスを活かした良い設計。
- Toast のスライドインアニメーションは自然。
- `prefers-reduced-motion` への配慮がある。

**課題**:
- ボタンの `:active` 状態が `background: var(--bg-hover)` だけで、タップの「弾み」感がない。`transform: scale(0.95)` や短い transition を加えるだけで触感が大きく向上する。FABだけは `:active` で `scale(0.92)` が入っており、このパターンを他のボタンにも展開すべき。
- タブ切り替え時にリストの内容が即座に差し替わり、遷移感がない。フェードやスライドの微小アニメーション（100-150ms）があると「切り替わった」ことが明確になる。
- メモアイテムの出現アニメーションがない。リストが再描画されるとき、全件が一瞬で出現する。staggered fade-in（50ms間隔で順にフェードイン）を加えると、リストに生命感が出る。
- 色ピッカーの開閉がアニメーションなし（`display: none -> flex`）。`opacity` + `transform: scale(0.95)` のトランジションで開く方が洗練される。

### 4. アクセシビリティ

**良い点**:
- `aria-label` がFAB、ヘッダーボタン、Voice関連ボタンに適切に付与されている。
- `:focus-visible` のスタイル（`2px solid var(--accent)`, `outline-offset: 2px`）がグローバルに定義されている。
- Toast に `role="status"` と `aria-live="polite"` が設定されている。
- `<html lang="ja">` が設定されている。

**課題**:
- コントラスト比の懸念: `--text-tertiary (#484f58)` on `--bg-base (#0d1117)` は約 2.8:1 で、WCAG AA の最低基準 4.5:1（通常テキスト）を満たさない。日付表示やプレースホルダーがこの色で表示されるため、ロービジョンユーザーには読みづらい。`#6e7681` 程度まで明るくする必要がある。
- `--text-secondary (#8b949e)` on `--bg-base (#0d1117)` は約 5.5:1 で AA をクリア。
- タブボタンにはtablistのrole/aria属性がない。`role="tablist"` / `role="tab"` / `aria-selected` を追加すべき。
- スワイプ操作はキーボード/スクリーンリーダーでアクセスできない。代替手段（長押しメニューまたはキーボードショートカット）が必要。
- カラーピッカーの色ドットに `aria-label`（"Blue", "Green" 等）がない。スクリーンリーダーユーザーには何のボタンかわからない。
- Markdownツールバーのボタンにも `aria-label` がない（`#`, `-`, `>` 等のテキストはあるが、支援技術にとって意味が不明瞭）。

### 5. 空間利用

**良い点**:
- ヘッダー高さ `3rem`（48px）はモバイルで適切。コンテンツ領域を最大化しつつ、操作に必要な面積は確保している。
- メモアイテムのパディング（`space-3 space-4` = 12px 16px）は密度と読みやすさのバランスが取れている。
- `safe-area-inset-bottom` への対応がFAB・Toastで入っており、ノッチ付き端末を考慮している。
- `interactive-widget=resizes-content` の viewport meta は、キーボード表示時のレイアウト問題を軽減する良い設定。

**課題**:
- メモアイテムの `padding-right: 3.5rem` はコピーボタン分の余白だが、コピーボタンが `position: absolute` で `top: space-3; right: space-3` に配置されているため、プレビューテキストが長い場合にボタンと重なる可能性がある。
- エディタの `editor-textarea` は `padding: space-4` (16px) で四方均等。左右は16pxで問題ないが、タイトル入力欄とテキストエリアの境界（`border-bottom: 1px solid var(--border-subtle)`）が視覚的に弱く、2つの入力フィールドの境界が曖昧に見える。
- Voice FAB の位置計算 `bottom: calc(env(safe-area-inset-bottom) + 1.5rem + 3.5rem + 1rem)` は正しいが、小さい画面（iPhone SE 667px高）でリスト最下部のメモアイテムが2つのFABに隠れる面積が大きい。リストの `padding-bottom` で補償すべき。

### 6. 感情的デザイン

**良い点**:
- ダークテーマの色調は目に優しく、夜間や暗い場所での使用に適している。「書くための道具」としての落ち着いた雰囲気が一貫している。
- Voice メモのパルスアニメーション（録音中の赤い点の脈動）は、「今、聴いている」という生き物的なフィードバックで心地よい。
- アーカイブ操作後のUndoトーストは「やっちまった」瞬間の安心材料として適切。
- アプリアイコン（暗い背景にメモ用紙 + 青いカーソル）は、アプリの性格をシンプルに伝えている。

**課題**:
- アプリ全体に「冷たい」印象がある。GitHub Darkのカラーパレットは機能的だが、感情的な温かみに欠ける。ヘッダーのアプリタイトル "QuickMemo" がプレーンテキストで、ブランド感がない。ロゴやカスタムフォントは不要だが、アクセントカラーでの一文字装飾など、微小な個性付けがあると愛着が湧く。
- 削除操作の「赤」が強すぎる。`--color-delete: #f85149` は警告色として強力だが、アーカイブ済みメモを削除する（掃除する）行為はそこまで危険ではない。「整理整頓」のニュアンスを持つ色やアイコンに緩和できる。
- 成功時のフィードバック（Copied, Exported, Settings saved）が全てテキストToastのみで、達成感の演出が薄い。コンフェッティは過剰だが、チェックマークの出現アニメーションなど、小さな「やった」感があると操作が楽しくなる。
- 音声メモ機能は高度だが、APIキー未設定時のメッセージ "Set your Gemini API key in Settings first" が事務的。「音声メモを使うには、まずSettingsでAPIキーを設定してください」のように、次のアクションを促すフレンドリーな文言に。

## Cross-Cutting Observations

### スワイプ一本足のアーキテクチャリスク
アーカイブ・削除の操作導線がスワイプ操作のみに依存している。これはアクセシビリティ（キーボード/スクリーンリーダー非対応）、発見性（アフォーダンスなし）、効率性（一括操作不可）の3つの観点で問題を抱えている。長押しコンテキストメニューの追加は、これらの問題を一度に緩和する構造的な改善となる。

### デザイントークンの拡張推奨
`border-radius`, `box-shadow`, `transition-duration` がトークン化されていない。現時点では885行のCSSで管理可能だが、機能追加に伴い一貫性が崩れるリスクがある。以下のトークンの追加を推奨:
```
--radius-sm: 0.375rem;
--radius-md: 0.5rem;
--radius-lg: 0.75rem;
--radius-full: 50%;
--shadow-elevated: 0 4px 12px rgba(0, 0, 0, 0.4);
--duration-fast: 150ms;
--duration-normal: 250ms;
--easing-standard: cubic-bezier(0.4, 0, 0.2, 1);
```

### パフォーマンスと知覚速度
`renderList()` は毎回 `memoListEl.textContent = ''` で全件再構築している。メモ数が少ないうちは問題ないが、100件を超えるとDOM再構築の "ちらつき" が知覚され、アプリの品質感が下がる。仮想スクロールまでは不要だが、差分更新または `DocumentFragment` でのバッチ挿入を検討すべき。
